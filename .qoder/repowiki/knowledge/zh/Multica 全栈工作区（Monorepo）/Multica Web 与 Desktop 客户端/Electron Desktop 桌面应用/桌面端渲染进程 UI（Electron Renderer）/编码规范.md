- 通过 `window.desktopAPI` / `window.daemonAPI` 访问 Electron 主进程能力，所有平台差异集中在 `platform/` 目录，业务组件不直接调用原生 API。
- 路由定义采用 `RouteObject[]` 数组 + `handle.title` 元数据模式，由 `TitleSync` 自动同步 `document.title`，新增页面只需追加路由项。
- 导航统一经由 `NavigationAdapter`（`push/replace/back/forward/openInNewTab`），跨工作区跳转和预工作区过渡路径在 adapter 层拦截后转为 store 操作或 overlay 打开，禁止直接操作 router。
- Tab 状态使用 Zustand 的 `persist` 中间件持久化，迁移通过 `migrate` 函数处理版本升级（v1→v2 分组、v2→v3 pinned、v3→v4 Tab→TabSession）。
- 工作区级路由统一形如 `/{workspaceSlug}/{route}/...`，路径在进入 store 前经 `sanitizeTabPath` 校验并归一化（如裸 slug 补全为 `/slug/issues`）。
- 桌面专属功能通过 `windowContext.kind === 'main'` 条件渲染（如 `DiagnosticRouteReporter`、`DesktopClientUsageReporter`、`UpdateNotification`），issue 窗口则走独立的 `IssueWindowContent` 分支。
