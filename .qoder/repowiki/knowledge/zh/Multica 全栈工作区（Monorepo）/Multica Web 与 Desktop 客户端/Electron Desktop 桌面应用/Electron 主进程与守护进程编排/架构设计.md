模块以 `index.ts` 为 Electron main 进程唯一入口，在 `app.whenReady()` 之后加载运行时配置、注册 `multica://` 自定义协议、获取单实例锁并创建主窗口；随后通过 `setupAutoUpdater`、`setupDaemonManager`、`setupLocalDirectory` 等初始化函数装配各子系统。

- 窗口与 IPC：`createWindow` / `createIssueWindow` 统一构造 BrowserWindow，挂载导航守卫、上下文菜单、快捷键、手势、下载对话框和渲染器恢复处理；所有 renderer→main 通信集中在 `ipcMain` 上（如 `shell:openExternal`、`window:*`、`notification:show`、`badge:set`、`runtime-config:get`、`freeze:*`），并通过 `../shared/*` 中的通道常量与类型保证契约。
- 守护进程编排：`daemon-manager.ts` 是核心，维护 active profile、健康轮询（5s）、状态机（installing_cli → starting → running/auth_expired/stopped）；通过 `cli-bootstrap.ts` 从 GitHub Release 下载并校验 checksum 安装 managed CLI，再按 bundled → managed → PATH 优先级解析二进制；`daemon-profile.ts` 派生 profile 名/端口/路径，`daemon-recovery.ts` 提供带退避、预算限制和 PID 防抖的恢复策略，`daemon-os.ts` 判断 WSL2 等外部托管场景，`daemon-auth-probe.ts` 探测登录是否过期。
- 会话与通知：`auth-session-coordinator.ts` 将 issue window 绑定到主窗口的 userId，账号切换时关闭不匹配的 issue 窗口；`notification-gate.ts` 去重系统通知，`renderer-recovery.ts` + `freeze-breadcrumb.ts` 在渲染器崩溃后持久化 breadcrumb 供下次启动上报。
- 更新：`updater.ts` 基于 electron-updater 启用静默下载+退出安装，按平台区分 x64/arm64 元数据通道，并提供设置开关与手动检查 IPC。
- 依赖方向：本模块仅向上依赖 `../shared/*` 的类型与通道定义，向下通过 Node fs/child_process/os 访问文件系统与子进程，不反向被 shared 层引用。
