该模块由一组相互协作的 Node ESM 脚本组成，围绕 `package.mjs`（主入口）组织：
- `package.mjs` 是发布编排核心，解析 `--mac/--win/--linux`、`--x64/--arm64`、`--all-platforms` 等参数，生成构建矩阵，依次调用 `bundle-cli.mjs` 编译 Go CLI、通过 `electron-vite build` 产出前端资源，再按目标逐个调用 `electron-builder` 并注入 `-c.extraMetadata.version`（来自 `git describe --tags --match 'v[0-9]*'` 的版本派生），同时根据宿主平台/架构设置 AppImage 默认产物、更新通道（latest / latest-arm64 / latest-x64）、macOS 最低系统版本与签名开关。
- `bundle-cli.mjs` 负责跨平台交叉编译 `server/cmd/multica` 到 `apps/desktop/resources/bin/`，使用 `GOOS/GOARCH` 环境变量进行静态 CGO 禁用构建，并在 macOS 上执行 ad-hoc codesign；当本地无 `go` 时优雅降级，依赖运行时自动安装。
- `dev.mjs` 是 `pnpm dev:desktop` 的启动器，串联 `bundle-cli → brand-dev-electron → electron-vite dev` 三步，并通过 `worktree-dev-env.mjs` 注入 `DESKTOP_RENDERER_PORT` 与 `DESKTOP_APP_SUFFIX` 实现多 worktree 并行开发。
- `worktree-dev-env.mjs` 用 POSIX cksum 对仓库路径求偏移，映射到 5174–6173 端口范围并避开 Chromium 受限端口（如 6000），同时生成 `<folder>-<offset>` 形式的 app suffix 用于 userData 与单实例锁隔离。
- `brand-dev-electron.mjs` 仅在 macOS 上通过 PlistBuddy 重写 `node_modules/electron` 的 `Info.plist` 中的 `CFBundleName`/`CFBundleDisplayName`，使其显示为 "Multica Canary <suffix>"，并通过 unlink+write 避免修改 pnpm store 硬链接。
- 测试文件 `package.test.mjs` 与 `worktree-dev-env.test.mjs` 直接 import 上述模块的纯函数（`normalizeGitVersion`、`parsePackageArgs`、`resolveBuildMatrix`、`builderArgsForTarget`、`envWithLocalBins`、`cksum`、`rendererPortForPath` 等），并对 `electron-builder.yml` 的 `files:!dist/**` 与 `publish.provider: generic` 做回归断言，确保多架构构建不互相污染产物。
