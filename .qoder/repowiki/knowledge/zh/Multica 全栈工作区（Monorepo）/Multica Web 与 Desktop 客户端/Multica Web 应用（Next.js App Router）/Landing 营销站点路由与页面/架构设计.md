采用 Next.js App Router 的路由组 `(landing)` 作为营销站点的根布局：`layout.tsx` 注入 `LocaleProvider`（来自 `features/landing/i18n`）、Google Font `Instrument Serif` 变量以及 JSON-LD 结构化数据；各子目录（`homepage`、`download`、`about`、`changelog`、`contact-sales`、`usecases/[slug]`）通过 `page.tsx` 暴露页面组件并声明 `Metadata`。

业务逻辑集中在 `features/landing/` 下，按职责分层：
- `components/`：页面级组合组件（`multica-landing.tsx` 组装 Header/Hero/Features/HowItWorks/OpenSource/FAQ/Footer），以及下载区专用组件（`download/hero`、`all-platforms`、`cli-section`、`cloud-section`、`os-icons`）和通用区块；`redirect-if-authenticated.tsx` 在客户端拦截已登录用户跳转至工作区。
- `i18n/`：自研轻量 i18n，通过 `context.tsx` 的 `LocaleProvider` + `dictionaryFactories` 按 `en/ja/ko/zh` 生成字典，使用 `createBrowserCookieLocaleAdapter` 持久化 locale 并通过 `router.refresh()` 重渲染。
- `utils/`：纯函数工具，如 `github-release.ts` 从公司 CDN 拉取 release manifest 并以 ISR `revalidate: 300` 缓存，`parse-release-assets.ts` 解析资产并按平台归类，`os-detect.ts`、`use-dashboard-cta.ts`、`use-github-stars.ts` 等供组件消费。

依赖方向单向：`(landing)` 路由 → `features/landing/*` → `@multica/core/*`（auth、workspace、paths、i18n 适配器、config），不反向依赖业务应用代码。
