以 `app/layout.tsx` 为唯一入口：服务端解析请求 locale 并注入 `@multica/core` 的 `CoreProvider`，再包裹 `WebProviders`（`components/web-providers.tsx`），后者集中提供 API/WS 地址、cookie 认证、用户 locale 同步、浏览器 OS 识别以及 `WebNavigationProvider` / `WebScrollRestorationProvider` 等 Web 平台适配，从而让所有子路由共享同一份状态与协议。

路由按 Next.js 路由组划分三类互斥场景：`(auth)` 处理登录/OAuth 回调/邀请/首次引导；`(landing)` 渲染官网静态内容并通过 MDX 支持多语言用例；`[workspaceSlug]/(dashboard)` 作为工作区上下文，把 agents/runtimes/issues/billing/skills/squads 等功能页委托给 `@multica/views` 共享组件。`platform/` 目录实现导航、滚动恢复、文档标题、用户 locale 同步等 Web 专属协议，供 `@multica/views` 在 Web 端调用；`lib/` 提供跨路由的纯函数工具（locale 路由、文档链接、工作区 slug 解析、用例 i18n 源）；`features/` 承载仅 Web 端的业务逻辑（如 auth cookie 写入、landing 页面组件与 i18n）。`next.config.ts` 通过 rewrites 将 `/v1`、`/api`、`/ws`、`/auth`、`/uploads` 转发至远端后端，并将 `/docs` 代理到外部文档站点，使各路由无需感知后端地址差异。
