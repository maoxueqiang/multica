模块按 Next.js Route Group `(auth)` 组织认证相关页面，每个 `page.tsx` 仅充当薄壳：读取 `useAuthStore` 的用户与会话状态，未登录时通过 `paths.login()` + `next=` 重定向回原目标；已登录则渲染来自 `@multica/views/*` 的共享业务组件（`LoginPage`、`InvitationsPage`、`InvitePage`、`OnboardingFlow`）。

- 登录入口 `/login`：处理 Google OAuth 启动、CLI 回调参数透传、以及桌面端 deep link (`multica://auth/callback`) 的手持令牌交接；登录后统一经 `resolvePostAuthDestination` 结合 `listMyInvitations` 决定去向。
- 回调页 `/auth/callback`：解析 Google 返回的 `code`/`state`，区分 CLI、Desktop、Web 三种流向——CLI 走 `redirectToCliCallback`，Desktop 走 deep link，Web 走 `loginWithGoogle` 并刷新 workspace 列表后跳转。
- 邀请与引导：`/invitations`、`/invite/[id]` 做登录守卫后直接渲染对应视图；`/onboarding` 与 `/workspaces/new` 复用同一 `OnboardingFlow`，前者用于首跑、后者为已 onboarded 用户新建工作区的显式入口。
- 会话标记：`features/auth/auth-cookie.ts` 提供 `setLoggedInCookie`/`clearLoggedInCookie` 操作 `multica_logged_in` Cookie，作为登录完成的轻量信号。
- 错误归一化：`callback-error.ts` 将 `@multica/core/api` 的 `ApiError` 映射为本地 `CallbackError` 联合类型，仅对客户端 4xx 错误给出可诊断的 kind，服务端错误一律降级为 `login_failed`。

依赖方向单向指向 `@multica/core/*`（auth/store、api、paths、workspace queries）、`@multica/ui` 基础组件与 `@multica/views/*` 业务视图，本模块不持有业务逻辑。
