- 每个认证路由 page 仅做 auth 守卫与渲染委派：先检查 `isLoading` 与 `user`，未登录时用 `router.replace(paths.login() + '?next=...')` 带原路径重定向，已登录再渲染 `@multica/views/*` 中的业务组件。
- 登录后跳转统一通过 `resolvePostAuthDestination(workspaces, hasOnboarded)` 计算目标，并在未 onboarded 且存在邀请时优先路由到 `/invitations`，避免遗漏邀请。
- 所有从 URL 或 OAuth state 传入的 `next`/`cli_callback` 等外部来源地址在跳转前必须经 `sanitizeNextUrl` / `validateCliCallback` 校验，防止开放重定向攻击。
- 异步副作用包裹在 `Suspense` 内并以空 fallback 渲染，配合 `useEffect` 中基于 `isLoading`/`user` 的重定向逻辑，避免闪烁。
- OAuth 回调错误通过 `callback-error.ts` 的 `CallbackError` 联合类型集中建模，UI 层用 switch 映射到 i18n key，服务端错误一律降级为通用 `login_failed`。
- 桌面端与 CLI 的令牌交接均通过 `window.location.href = 'multica://auth/callback?token=...'` 深链完成，而非 HTTP 请求，保持跨进程安全传递。
