模块以 `@multica/core` 为 npm 包名，通过 `package.json` 的 `exports` 字段精细暴露子路径（如 `./issues/*`、`./agents/stores`），对外仅暴露稳定契约。

内部按领域划分目录：每个业务域（agents、chat、inbox、issues、billing、runtimes、workspace、projects、plugins、labels、quick-actions、autopilots、squads、github/lark/slack/dingtalk/wecom/telegram 等集成）均遵循统一分层——`queries.ts`/`mutations.ts` 调用 `api/index.ts` 中的 `ApiClient`/`WSClient`；`stores/` 或独立 store 文件用 Zustand 管理本地状态；`use-*` hooks 组合查询与 store；`ws-updaters.ts` 处理实时推送。

横切基础设施集中在根级：`query-client.ts` 配置 TanStack Query 默认策略（staleTime: Infinity、gcTime: 10min、refetchOnReconnect）；`provider.tsx` 暴露 `QueryProvider`；`platform/` 提供 `CoreProvider`、`AuthInitializer`、`defaultStorage`、`createPersistStorage`、`workspace-storage`（按 workspace 隔离存储）、`system-notification`、`session-cleanup`；`api/` 提供 HTTP 与 WebSocket 客户端及全局单例代理 `api`；`types/` 集中导出所有跨端共享类型；`i18n/`、`feature-flags/`、`realtime/`、`diagnostics/`、`analytics/`、`drafts/`、`navigation/`、`paths/`、`permissions/` 等提供通用能力。

依赖方向严格单向：各领域模块可引用 `api`、`platform`、`types`、`realtime`、`i18n`、`feature-flags` 等基础层，但基础层不反向依赖任何领域；`views` 与 `ui` 被明确排除在本模块之外，保持 core 与 ui 相互独立。
