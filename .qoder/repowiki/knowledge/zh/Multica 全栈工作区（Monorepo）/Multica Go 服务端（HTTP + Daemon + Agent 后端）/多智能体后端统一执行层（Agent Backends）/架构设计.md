模块以 `agent.go` 中定义的 `Backend` 接口（`Execute(ctx, prompt, opts) (*Session, error)`）为核心契约，所有具体智能体（claude、codex、copilot、cursor、hermes、qwen、grok、openclaw、pi、traecli、qoder、mcode、dim、zeroclaw、codebuddy、deveco、kiro、antigravity、opencode、codearts、dsh、reasonix、kimi、qwenpaw 等）各自实现该接口并集中由 `New()` switch 分发注册到 `SupportedTypes` 白名单。

- 进程生命周期：`launch.go` 中的 `Command`/`exec`/`execVia` 是唯一的进程创建边界，强制通过 `newRuntimeCmd` 设置进程组与 SIGKILL 取消，并通过 `filterLaunchPrefix` 按协议族黑名单过滤自定义 runtime profile 的 fixed_args，防止覆盖 stream-json 等协议标志；`logAgentCommand` 对 argv 做脱敏日志。
- 运行时身份：`builtin_runtimes.go` 定义 `BuiltinRuntime` 描述符（如 omp 复用 pi 协议），`ResolveBackend`/`NewRuntime` 将运行时 ID 路由到对应协议族后端并应用可插拔的 `backendOverrideApplicator`。
- 流式传输：`stream_scanner.go` 提供带 32 MiB 行上限的 `bufio.Scanner`，各后端通过它读取行分隔 JSON 事件；`acp_terminal.go` 在 ACP 终端能力下以受控尾缓冲 + UTF-8 安全截断的方式管理子 shell 进程。
- 错误诊断：`exec_format.go` 针对 npm postinstall 缺失导致的 ENOEXEC 生成可读修复指令（含 shell 适配的 `ExecFormatRepair`）。
- 依赖方向：后端文件仅依赖本包公共类型（`Config`、`Command`、`Session`、`Message`、`Result`）与标准库，不反向引用上层 daemon/service，保证新增 provider 只需实现 `Backend` 并登记到 `SupportedTypes`。
