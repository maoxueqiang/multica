- 每个资源处理器将数据库行转换为独立的 Response 结构体（如 `ProjectResponse`、`WorkspaceResponse`、`SquadResponse`），并通过 `xxxToResponse` 函数集中映射字段，避免在 handler 中散落 struct 构造。
- 写操作在打开事务前先做参数与枚举校验（如 status/priority/issue_prefix），失败直接返回 400，确保无效请求不占用数据库连接。
- 涉及多表变更的操作统一通过 `h.TxStarter.Begin` + `qtx := h.Queries.WithTx(tx)` 模式执行，并在 defer 中 Rollback，提交后调用 `h.publish` 广播对应事件。
- 错误处理统一封装为 `writeError` 或专用 helper（如 `writeProjectWriteError`、`failWorkspaceDelete`），并将 CHECK 约束冲突映射为 400、唯一键冲突映射为 409、锁竞争映射为 503。
- 权限校验集中在前置步骤：先取 workspace 上下文，再调用 `requireWorkspaceRole` / `workspaceMember` / `canManageSquad` / `memberCanWireAgent` 等函数，未通过即返回 401/403 并提前 return。
- 对外暴露的敏感字段（如 MCP server config、avatar_url）通过 `acceptAvatarURL` 白名单过滤或通过只读响应结构体剔除，避免凭据泄露到日志或响应体。
