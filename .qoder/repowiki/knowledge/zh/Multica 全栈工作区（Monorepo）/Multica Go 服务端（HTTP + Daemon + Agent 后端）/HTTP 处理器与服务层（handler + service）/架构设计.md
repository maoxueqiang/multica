本模块由 handler 与 service 两个相邻包构成请求处理的两层：
- handler 层以 `internal/handler.Handler` 为装配中心，集中持有 DB 连接、realtime.Hub、events.Bus、service.*Service、存储、限流器、第三方集成客户端等依赖；所有子目录（agent、chat、issue、project、autopilot、plugin、integration、dashboard、auth、cloud、daemon 等）按资源域拆分文件，但都通过同一个 Handler 实例访问共享基础设施。
- service 层提供 TaskService、PluginService、IssueService、AutopilotService、EmailService 等无状态或轻状态的业务编排对象，被多个 handler 复用，避免跨文件的重复事务/事件/权限逻辑。
- 两者通过构造函数注入耦合：`handler.New` 内部构造各 Service 并注入到 Handler，再由 `cmd/server/router.go` 把单一 Handler 实例挂载到 chi 路由器；handler 调用 service 完成写操作后统一通过 `h.publish` / `h.publishTask` / `h.publishChat` 经 events.Bus 广播变更，供 realtime.Hub 推送给前端与 daemon。
- 横切关注点集中在 handler 根文件：`resolveActor` 区分 agent/member 身份、`requireWorkspaceMember/Role` 做工作区级 RBAC、`writeJSON/writeError/writeRevisionConflict` 统一响应格式、`parseUUIDOrBadRequest` 统一参数校验、`channelDeliversFiles` 声明式能力注册。
- 第三方集成（Slack/DingTalk/Lark/WeCom/Telegram/Composio/GitHub PR snapshot）以可选字段注入 Handler，未配置时返回 503，保证自托管部署可优雅降级。
- 内置 Agent/Mika 指令与 SKILL.md 通过 `go:embed` 随二进制发布，由 service 层在运行时组装提示词，遵循“渐进式加载”约定，不在 brief 中全量内联。
