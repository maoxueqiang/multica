本模块位于 `server/internal/handler`，围绕 `Handler` 结构体暴露一组 `http.HandlerFunc`，通过 go-chi/v5 路由挂载到 `/api/autopilots/*` 与 `/api/webhooks/autopilots/{token}`。
- 资源层：`autopilot.go` 实现 Autopilot、Trigger、Run、Subscriber、Collaborator 的 REST 接口（List/Create/Get/Update/Delete），使用 `h.Queries`（sqlc 生成的 `db.Queries`）访问 PostgreSQL，并通过 `h.TxStarter` 在事务中串行化订阅者写入（`LockSubscriberWrites` + `LockActiveMember`）以避免成员撤销竞态。
- 权限边界：写操作由 `requireAutopilotWrite`（创建者/owner/admin/显式 collaborator）与更窄的 `requireAutopilotAccessManagement`（仅创建者/owner/admin）双重守卫；读路径按 `can_write` / `can_manage_access` 字段裁剪 webhook token 等敏感信息。
- Webhook 入口：`autopilot_webhook.go` 中的 `HandleAutopilotWebhook` 是独立于认证组的公开端点，以 URL path 中的 `awt_` 前缀随机令牌为凭据，流程为：IP 速率限制 → 令牌查找 → 256 KiB 体大小限制 → JSON 规范化为 `WebhookEnvelope` → 提取 provider 专属去重键（GitHub `X-GitHub-Delivery` / generic `Idempotency-Key`）→ HMAC-SHA256 签名校验 → 插入 `webhook_delivery`（queued）→ 处理 dedupe 冲突 → 拒绝/忽略/放行 → 调用 `AutopilotService.AdmitAutopilotWebhookDelivery` 异步派发并唤醒 worker。
- 事件过滤：`event_filters` 以 JSONB 存储，写入时经 `validateWebhookEventFilters` 严格校验，运行时通过 `webhookEventAllowedByTriggerScope` 匹配 provider.event.action 三元组。
- 辅助能力：`autopilot_cron_preview.go` 提供只读的 cron 表达式预览（委托给 `service.NextOccurrencesAfterUTC`），`trigger_test.go` 覆盖评论中 `/note` 短路逻辑与 agent/squad mention 检测。
- 依赖方向：handler → service（业务规则如模板校验、cron 计算）、middleware（上下文注入）、metrics/analytics（指标上报）、pkg/db/generated（SQL 查询），不反向依赖上层路由注册。
