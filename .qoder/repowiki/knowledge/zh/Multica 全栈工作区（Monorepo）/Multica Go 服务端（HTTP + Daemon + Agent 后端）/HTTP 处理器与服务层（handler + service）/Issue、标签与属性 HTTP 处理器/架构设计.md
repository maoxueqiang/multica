本模块位于 server/internal/handler，以 chi/v5 路由承载 Issue 相关 REST API，按职责拆分为多个文件：issue.go（核心 Issue 读写、状态解析与归档竞态保护）、issue_status.go（工作区状态目录 CRUD）、label.go（标签 CRUD）、property.go（自定义属性定义与值写入）、issue_metadata.go（单键原子元数据 KV）、issue_view.go（保存的过滤视图）、issue_table_*.go（表格查询、分组、行、筛选器、Facet）以及 issue_move.go / issue_trigger.go / issue_reaction.go / issue_child_done.go / issue_limit.go 等辅助操作。
- 依赖方向单向向下：HTTP 层通过 h.Queries（sqlc 生成的 db.Queries）访问 PostgreSQL，并通过 internal/issuestatus、internal/dispatch、internal/channelmedia、internal/middleware、internal/service 等子包完成状态解析、事件发布、通道媒体合并与权限校验；不直接持有业务领域模型。
- 统一使用 Handler 方法接收 *http.Request，借助内部工具函数 parseUUIDOrBadRequest、requireUserID、requireWorkspaceRole、resolveWorkspaceID、writeJSON/writeError 进行参数解析、鉴权与响应封装。
- 复杂查询（表格）采用 REPEATABLE READ 只读事务快照 + 8 秒超时上下文，避免长查询阻塞并发写；分页使用基于 cursor 的游标结构 issueTableCursor。
- 状态写入走 resolveIssueStatusKey → assertIssueStatusStillActive 的两阶段校验，配合 catalog 共享锁解决归档竞态；属性与标签各自维护白名单常量（validPropertyTypes、validPropertyIcons、validIssuePriorities 等）在边界做严格校验。
