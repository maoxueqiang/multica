- 每个 HTTP 处理器以 (h *Handler) 方法形式实现，先调用 requireUserID/requireWorkspaceRole/resolveWorkspaceID 完成鉴权与 workspace 解析，再解码请求并调用 writeError/writeJSON 返回。
- 输入校验集中在独立的 validate/normalize 函数（如 validateLabelName、validatePropertyName、normalizeColor、validateIssueMetadataValue），错误通过 writeError 返回 400，保持处理器逻辑简洁。
- 对外响应类型与数据库行类型之间通过 toResponse 转换函数（如 labelToResponse、propertyToResponse、issueStatusToResponse）解耦，时间字段统一用 timestampToString 序列化。
- 枚举类字段使用包级白名单切片或 map 常量（validIssuePriorities、validPropertyTypes、validPropertyIcons、reservedPropertyNames 等）在 API 边界做允许值校验。
- 对可能产生并发冲突的状态写入，统一采用预解析 + catalog 共享锁重校验的模式（resolveIssueStatusKey → LockIssueStatusCatalogShared → 再次 Resolve），并将归档竞态映射为 409 Conflict。
- 表格查询使用 json.RawMessage 透传 query/display 等客户端契约字段，并在 decodeIssueTableJSON 中启用 DisallowUnknownFields 与 MaxBytesReader 做严格反序列化和体积限制。
