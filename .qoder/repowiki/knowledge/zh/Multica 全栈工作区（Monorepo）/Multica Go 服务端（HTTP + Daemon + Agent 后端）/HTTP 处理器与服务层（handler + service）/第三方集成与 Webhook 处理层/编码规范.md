- 每个外部集成以独立文件组织，handler 方法先检查对应服务字段是否为 nil（如 `h.SlackInstall == nil`、`h.Composio == nil`），返回 503 表示集成未启用，使 UI 可隐藏对应入口。
- 敏感凭据（access_token、webhook_secret、bot token）一律通过 `seal*/open*` 或 `Encrypt/Decrypt` 包装后再落库，响应中从不回显明文。
- 所有 handler 统一通过 `parseUUIDOrBadRequest`、`requireUserID`、`roleAllowed` 等辅助函数做参数校验与权限判断，并调用 `writeError`/`writeJSON` 输出结构化响应。
- 创建/删除连接后通过 `h.publish(protocol.EventXxx, workspaceID, actorType, actorID, payload)` 广播实时事件，供前端 WebSocket 失效缓存。
- Webhook 入站路径先做 IP/Token 双层滑动窗口限流（`DefaultWebhookAbsoluteIPRateLimit`、`DefaultWebhookIPRateLimit`、`DefaultWebhookRateLimit`），超限直接拒绝而不进入数据库查询。
- 持久化投递采用 Postgres 队列 + `SKIP LOCKED` 抢占模式，worker 用 lease token 防并发重复，失败按 `DispatchAttempts` 指数退避重试，最多 5 次后标记为 failed。
