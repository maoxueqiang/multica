本模块位于 `server/internal/handler` 下，按“外部系统 + 通用能力”分层组织：
- 各集成独立文件（`github.go`、`slack.go`、`dingtalk.go`、`lark.go`、`wecom_web.go`、`telegram.go`、`integrations_composio.go`），每个文件定义该系统的 HTTP handler、请求/响应结构体，并通过注入的 `*service.*Install`/`*BindingTokens`/`Composio` 客户端调用 `internal/integrations/*` 子包完成协议细节，handler 本身只负责鉴权、参数解析、错误码映射与通过 `h.publish` 广播事件。
- VCS 子系统由 `vcs.go`（连接 CRUD、加密封装）、`vcs_webhook.go`（`POST /api/webhooks/vcs/{connectionId}` 入口，按 provider 分发 pull_request/ci_status）组成，借助 `internal/integrations/vcs` 的 `Provider` 接口统一签名验证与事件解析，再复用 issue 关联与 PR 状态聚合逻辑。
- 通用 webhook 基础设施集中在 `webhook_delivery.go`（投递记录 CRUD、重放）、`webhook_delivery_worker.go`（基于 Postgres `SKIP LOCKED` 的持久化队列 worker，带指数退避重试与 lease 竞争处理）、`webhook_rate_limiter.go`（滑动窗口限流，内存与 Redis 两种实现共享同一 `SlidingWindowRateLimiter` 接口）。worker 通过 `AutopilotService.DispatchAutopilotForWebhookDelivery` 触发下游 autopilot 运行。
- 依赖方向单向：handler → `internal/integrations/*`、`internal/service`、`pkg/db/generated`、`pkg/protocol`；不反向引用业务 service，仅通过 `Handler` 字段注入依赖，便于测试替换。
