- 每个资源定义独立的 Response DTO 并通过单独的 toResponse 函数将 DB 行转换为 JSON，避免在 handler 中散落映射逻辑。
- 对外部可替换的后端（Redis/内存）一律以接口（如 LivenessStore、UpdateStore、ModelCatalogStore）抽象，并提供 Noop/InMemory 默认实现与 Redis 实现，由外部装配。
- handler 方法统一通过 requireUserID / requireWorkspaceID / requireRuntimeReadAccess 等辅助函数完成鉴权与上下文解析，失败时直接 writeError 返回。
- 敏感字段（gateway token、composio allowlist、custom_env）在响应构造阶段进行掩码或仅暴露元信息（has_custom_env/key_count），禁止将明文值写入 JSON。
- 调度类错误统一通过 admission.go 中的 DispatchStatus/ReasonCode 枚举表达，writeDispatchBlocked 同时输出兼容旧客户端的 error 字段与稳定的 reason_code。
- Redis 键采用 mul:* 命名空间前缀并按资源类型细分（如 mul:runtime:hb:、mul:{runtime_pending}:local_skill:list:），key 构造集中为 local 函数。
