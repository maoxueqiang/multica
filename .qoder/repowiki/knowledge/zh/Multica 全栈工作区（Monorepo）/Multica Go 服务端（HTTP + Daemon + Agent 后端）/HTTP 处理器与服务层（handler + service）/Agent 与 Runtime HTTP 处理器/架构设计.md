本模块是 server/internal/handler 下按资源划分的 HTTP 处理器集合，统一挂载在 chi router 上，通过 Handler 结构体暴露方法并依赖 service、pkg/db/generated（sqlc）、dispatch、metrics 等下游。
- 资源拆分：agent.go + agent_*.go 负责 Agent 全生命周期（CRUD、权限、环境、技能、对话启动器、avatar、builder）；runtime.go + runtime_*.go 负责 Runtime 列表/绑定/解绑/使用量/可见性/自定义名/profile；actor_guards.go 提供 RequireHumanActor 中间件拦截机器凭证；admission.go 定义跨入口统一的 DispatchStatus/DispatchOutcome 调度准入契约。
- 可插拔存储抽象：LivenessStore（runtime_liveness_store.go）、UpdateStore（runtime_update.go）、LocalSkillListStore/ImportStore（runtime_local_skills_redis_store.go）、ModelCatalogStore（runtime_model_catalog_redis_cache.go）、ModelsRedisStore（runtime_models_redis_store.go）均定义为接口，并提供 InMemory/Noop 默认实现与 Redis 实现，由外部 wiring 注入，使单节点与多节点部署共用同一 handler 逻辑。
- 安全边界：敏感字段（gateway token、composio allowlist、custom_env）在 agentToResponse 中做掩码/脱敏；RequireHumanActor 基于 X-Actor-Source 头拒绝 task_token/cloud_pat 访问人类专属端点；admission 的错误仅返回枚举化的 ReasonCode，不泄露私有目标信息。
- 响应建模：每个资源都有独立的 DTO（AgentResponse、AgentRuntimeResponse、RuntimeUsageResponse 等），DB 行到 JSON 的转换集中在 toResponse 函数内完成，保证 wire 格式稳定且可独立演进。
