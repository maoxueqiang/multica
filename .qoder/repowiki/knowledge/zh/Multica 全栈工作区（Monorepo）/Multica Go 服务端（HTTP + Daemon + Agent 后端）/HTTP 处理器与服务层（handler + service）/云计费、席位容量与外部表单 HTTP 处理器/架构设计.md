本模块由五个独立的 handler 文件组成，统一挂载在 `server/internal/handler` 包下，通过共享的 `Handler` 结构体（含 `CloudRuntime`、`SeatCapacity`、`Queries`、`FeatureFlags`、`Analytics`、`Metrics` 等依赖）对外暴露方法。
- 云计费代理（cloud_billing.go）：所有 `/api/cloud-billing/*` 与 `/api/cloud-subscriptions/*` 路由最终通过 `proxyCloudRuntime` / `proxyCloudSubscription` 转发到 `internal/cloudruntime` 的同一后端服务；Stripe Webhook 走独立路径 `/api/webhooks/stripe`，以字节为单位透传 body 并原样转发 `Stripe-Signature` 头，仅做 IP 级速率限制与 1MiB body 上限防护。工作区订阅端点额外通过 `requireCloudSubscriptionWorkspace` 注入 workspace_id、校验成员角色（owner/admin），并对 Idempotency-Key 做白名单长度限制。
- 席位容量（seat_capacity.go）：不直接暴露 HTTP 路由，而是提供 `reserveInvitationCapacity`、`beginShareJoinCapacity`、`confirmCapacityIntent`、`compensateCapacityIntent` 等能力函数，被其他业务 handler 调用；通过 `SeatCapacityLocker` 按 workspace 加锁，使用 seatcapacity 包的意图表（intent/outbox）实现幂等预留/消费/确认/释放四阶段，失败时回退为异步重试。
- 客户端用量（client_usage.go）：`UpsertClientUsage` 接收桌面端 runtime probe，经正则与枚举校验后写入 `client_usage_daily`，并在有 workspace 时先获取 `LockWorkspaceForChatSessionCreate` 行锁再 upsert，避免与 workspace 删除竞态。
- 反馈（feedback.go）：`CreateFeedback` 对 message/context 做长度与格式校验，基于 DB 的 `CountRecentFeedbackByUser` 实现每小时 per-user 限流，并将平台元数据与图片标记写入 analytics/metrics。
- 销售联系（contact_sales.go）：公开无鉴权的 POST `/api/contact-sales`，通过白名单域名表拒绝个人邮箱、按 email 小时限流、记录提交者真实 TCP 远端 IP，并产出 analytics 事件。
依赖方向：handler → internal/cloudruntime / internal/seatcapacity / internal/analytics / internal/metrics / pkg/db/generated；各 handler 之间无相互调用，职责边界清晰。
