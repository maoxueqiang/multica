- 每个 provider 的准备逻辑拆分为独立文件（如 `codex_home.go`、`hermes_home.go`、`openclaw_config.go`、`cursor_mcp.go`），由 `Prepare`/`Reuse` 根据 `params.Provider` 字符串分派调用。
- 所有对 WorkDir 的写操作统一走 `recordMkdirAll`/`recordWriteFile` 记录到 `sidecarManifest`，禁止直接 `os.WriteFile`，以便 `CleanupSidecars` 精确回滚。
- 对 user-owned 目录的注入采用“标记块”语义：运行时 brief 用固定 HTML 注释包围，`writeRuntimeConfigFile` 追加或原地替换，`CleanupRuntimeConfig` 严格还原原始字节。
- provider 行为差异通过 switch 表集中维护（`skillsDirPath`、`runtimeConfigPath`），新增 provider 需同时补齐技能目录映射与配置文件名映射。
- 跨进程边界使用私有结构体包装敏感字段（如 `preparationOpenclawGatewayPin` 去掉 MarshalJSON），避免公开类型序列化泄露 token。
- 错误分类通过 `ErrorKind` 字符串在 helper 与父进程间传递（如 `openclaw_cli_timeout`），再由 `rehydratePreparationError` 重建 typed error，保持 `errors.Is` 语义。
