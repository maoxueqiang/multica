模块由三个职责互补的文件组成：
- `runtime_mcp.go`：负责“运行时 MCP 发现与合并”。通过 `loadRuntimeMcpServerConfigs` 按 provider（claude/codearts/codex/cursor/opencode/openclaw/kimi/omp 等）解析各自的用户配置文件路径、JSON/JSONC/TOML 格式及键路径，再经 `mergeRuntimeAndAgentMcpConfig` 将运行时服务器作为基础层、Agent 同名项覆盖，最终产出仅含 `mcpServers` 的任务局部 JSON；`listRuntimeLocalMcpServers` 提供脱敏摘要用于 Agent 能力展示。Claude 插件目录会被额外扫描并去重。
- `remote_mcp_broker.go`：负责“Remote MCP 代理网关”。`startTaskRemoteMCPBrokers` 为每个 `remotemcp.Connection` 监听一个 `127.0.0.1:0` 端口，生成随机 path token 并通过 `remoteMCPProxy.ServeHTTP` 转发 JSON-RPC 请求到远端 HTTPS 端点；内置请求大小限制（1MB）、并发信号量（8）、调用计数上限（256）、白名单方法（initialize/ping/tools/list/call 等）以及 ApprovedTools 校验与 schema drift 检测，失败时返回标准 JSON-RPC 错误码。
- `client.go`：守护进程对服务端控制平面的 HTTP 客户端，其中 `ResolveRemoteMCPCredential` 是 broker 获取凭据头的回调实现，`daemonCommonCapabilities` 声明 `DaemonCapabilityRemoteMCPV1` 能力位，使服务端知道该 daemon 支持 Remote MCP 代理。
依赖方向：broker 依赖 `server/pkg/remotemcp` 做远端发现与安全客户端；runtime_mcp 仅依赖标准库与 toml 解析；client 被上层调度器调用以完成生命周期管理。三者共同构成“本地配置注入 + 远端调用代理”的 MCP 生命周期边界。
