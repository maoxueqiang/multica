模块以 `execenv.go` 中的 `Prepare` / `Reuse` 两个入口为核心：接收 `PrepareParams`/`ReuseParams`，计算并锁定 `envRoot`（`workspacesRoot/{workspaceID}/{taskID}`），再根据 `Provider` 分支调用各 provider 专用准备函数（`codex_home.go`、`hermes_home.go`、`openclaw_config.go`、`cursor_mcp.go`、`qwenpaw_workspace.go`、`reasonix_permissions.go` 等），最终返回包含各 provider 路径字段的 `Environment`。
- 文件写入通过 `sidecar_manifest.go` 的 `recordMkdirAll`/`recordWriteFile` 追踪，持久化为 `{envRoot}/.multica_sidecar_manifest.json`，由 `CleanupSidecars` 反向删除；对本地目录任务提供 `rollBackPreparedSidecars` 失败回滚。
- 运行时 brief 通过 `runtime_config.go` 的 `InjectRuntimeConfig`/`CleanupRuntimeConfig` 以 HTML 注释标记块（`<!-- BEGIN MULTICA-RUNTIME -->` … `<!-- END MULTICA-RUNTIME -->`）追加到 `CLAUDE.md`/`AGENTS.md`/`QWEN.md`/`CODEBUDDY.md`，保证用户原有内容字节级还原。
- 进程隔离在 `isolation.go`：`PrepareIsolated`/`ReuseIsolated` 启动同一二进制下的 `__multica_execenv_prepare` helper 子进程，通过 stdin/stdout JSON 协议传递请求/响应，并使用平台进程树控制器（`envlock_unix.go`/`envlock_windows.go`）实现超时可杀。
- 工作区 git worktree 模式由 `local_worktree.go` 处理，使多个任务共享同一仓库时各自拥有独立分支。
- 依赖方向单向向外：仅依赖 `server/internal/runtimeapps`、`server/pkg/agent`、`server/internal/skill`，不反向被 daemon 调度层以外的包引用。
