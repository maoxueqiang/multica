模块以 `cache.go` 中的 `Cache` 结构体为核心，围绕一个根目录（`root/workspaceID/`）组织多个 bare 仓库，并通过 `sync.Map` 中每个 bare 路径对应的 `repoLock` 实现细粒度互斥：普通操作通过 `LockContext` 串行化，低优先级维护通过 `tryLockMaintenance` 在空闲时运行并可被前台任务抢占取消。

内部职责分层清晰：
- Git 子进程封装层：`newGitCommand` + `runGit*` / `runGitOutput*` / `runGitCombinedOutput*` 系列函数统一设置工作目录、继承的环境变量（含 `GIT_CONFIG_*` 安全配置与 `GIT_TERMINAL_PROMPT=0`），并通过 `processtree` 包执行带超时和进程树清理的命令。
- 仓库生命周期：`Sync`/`gitCloneBare`/`gitFetch` 负责克隆、增量 fetch、以及从旧版 mirror-style refspec 迁移到现代 `refs/remotes/origin/*` 布局；`ensureRemoteTrackingLayout` 保证后续 fetch 不会与 worktree 锁定的 `refs/heads/*` 冲突。
- 工作树创建：`CreateWorktree` 是对外主入口，根据 `WorktreeParams.IsolatedGitMetadata` 选择两种模式——共享 bare 的 linked worktree 或 `.git` 独立于工作目录的 isolated checkout（后者通过 `git clone --local` + 临时 remote `multica-cache` 再替换回真实 origin，支持 partial clone 的 promisor 远程）。
- 引用解析：`getRemoteDefaultBranch` 按多级策略（`origin/HEAD` → `main/master` → bare HEAD 映射 → 唯一 origin/* → 遗留 bare HEAD）确定默认分支，避免在多分支场景下错误猜测。
- Co-authored-by 钩子：通过 `prepareCommitMsgHook` 生成 shell 脚本写入 git common dir 的 `hooks/prepare-commit-msg`，由 `WriteCoAuthoredByState` 原子发布状态文件，`ReconcileCoAuthoredByHooks`/`ReconcileCoAuthoredByHookInCheckout` 在裸仓和工作树两个位置同步钩子。
- 使用痕迹与 GC 配合：`MarkUsed`/`LastUsed` 在 bare 仓内写 `.multica_last_used` 时间戳，供外部垃圾回收判断闲置仓库。

依赖方向单向向外：仅依赖标准库、`log/slog` 和本项目 `server/internal/daemon/processtree`（用于进程树管理与输出收集），不反向依赖 daemon 的其他组件。
