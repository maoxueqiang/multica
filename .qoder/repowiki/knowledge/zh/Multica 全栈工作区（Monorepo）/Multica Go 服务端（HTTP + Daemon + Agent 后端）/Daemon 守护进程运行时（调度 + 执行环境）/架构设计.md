daemon_core 作为入口，通过 agents_probe/agents_refresh 发现并刷新可用 Agent，再根据请求类型构造 ExecEnv（execenv 子模块）装配隔离工作目录、provider 配置与 MCP 侧车；随后调用 processtree 启动子进程树并借助 repocache 复用 bare clone 的 Git 仓库 worktree 作为执行上下文。execenv 负责按 provider（Codex/Hermes/OpenClaw/Cursor/Reasonix/QwenPaw 等）注入技能、会话、内存与权限策略，并通过 isolation_unix/isolation_windows 实现跨平台隔离；进程退出后由 daemon_core 的 GC 流程回收临时目录与缓存条目。三者通过接口契约协作：daemon_core 持有 ExecEnv 构建器与 ProcessTree Controller，不直接操作文件系统或进程细节，从而保持调度层与执行层的解耦。
