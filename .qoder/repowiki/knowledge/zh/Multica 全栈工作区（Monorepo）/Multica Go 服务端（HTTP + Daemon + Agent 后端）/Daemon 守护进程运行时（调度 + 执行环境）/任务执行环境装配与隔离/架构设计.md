模块以 `execenv.go` 中的 `Prepare` / `Reuse` 两个入口为中心：`Prepare` 通过 `claimEnvRoot` 对 envRoot 加独占锁、清理旧内容、创建 `workdir`/`output`/`logs`/`multica-config` 子树，再根据 `params.Provider` 分支调用各 provider 专用准备函数（`prepareCodexHomeWithOpts`、`prepareHermesHome`、`prepareOpenclawConfig`、`prepareCursorMcpConfig`、`prepareQwenpawWorkspace`、`writeReasonixProjectConfig`），并通过 `sidecarManifest` 记录所有写入以便 `CleanupSidecars` 精确回滚；`Reuse` 在已有 workdir 上刷新上下文文件与 provider 配置。`context.go` 负责把 `TaskContextForEnv` 写为 `.multica/daemon_task_context.json`、`.multica/project/resources.json` 以及按 provider 映射到各自 skills 目录的 SKILL.md，并统一处理 YAML frontmatter 的 name 字段规范化。`isolation.go` 将 Prepare/Reuse 下沉到独立的 `__multica_execenv_prepare` 子进程，通过 stdin/stdout JSON 协议通信，使阻塞的 FS 调用可被 kill 掉而不泄漏 goroutine。`runtime_config.go` 用 HTML 注释标记 `<!-- BEGIN MULTICA-RUNTIME -->...<!-- END MULTICA-RUNTIME -->` 把 brief 注入 CLAUDE.md/AGENTS.md 等运行时配置文件，保证幂等且可剥离。平台差异通过 `*_unix.go` / `*_windows.go` 成对文件拆分（如 `envlock`、`isolation`、`codex_home_link`、`task_temp`）。依赖方向单向向外：仅依赖 `server/internal/runtimeapps` 与 `server/pkg/agent` 的类型，不反向被上层业务逻辑引用。
