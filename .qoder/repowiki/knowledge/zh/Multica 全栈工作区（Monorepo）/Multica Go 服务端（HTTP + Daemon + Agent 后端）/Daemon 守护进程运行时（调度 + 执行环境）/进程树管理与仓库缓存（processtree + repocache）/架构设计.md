模块由两个相互协作的子包组成：
- `processtree`：通过 `run.go` 暴露统一的 `Run/Output/CombinedOutput` 入口，内部用 build tag 分离 `controller_unix.go`（使用 Unix 进程组 `Setpgid` + SIGTERM/SIGKILL 整组终止）和 `controller_windows.go`（使用 Windows Job Object + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）。所有外部命令在启动后调用 `controller.attach` 加入进程组/Job，取消时先优雅发送信号，再等待 `gracefulStopTimeout`，超时后强制 kill，最后 `finish` 轮询直到整个进程树消失。
- `repocache`：以 `Cache` 结构体为核心，按 workspaceID 组织 bare clone 目录；每个 bare repo 通过 `sync.Map` 映射到独立的 `repoLock`，实现前台操作优先、后台 maintenance 可被抢占的互斥模型（`LockContext` 与 `tryLockMaintenance`）。Git 子进程统一经 `newGitCommand` 构造，设置 `GIT_TERMINAL_PROMPT=0`、`safe.directory=*` 并通过 `processtree` 运行，从而保证 git fetch/clone/worktree 等长时间操作的进程树也能随上下文取消而回收。缓存还维护 `refs/remotes/origin/*` 现代布局、`lastUsedFile` 时间戳用于 GC 淘汰，以及可选的 isolated checkout 模式（本地克隆 + promisor remote）。
依赖方向单向：`repocache` 依赖 `processtree`，`processtree` 不反向依赖任何上层业务。
