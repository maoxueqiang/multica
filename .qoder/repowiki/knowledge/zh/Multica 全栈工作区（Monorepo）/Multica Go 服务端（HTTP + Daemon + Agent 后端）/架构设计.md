server 模块按职责切分为四层并通过依赖注入串联：
- cmd/server 作为唯一可执行入口，初始化数据库、特征开关、指标与日志后组装 chi 路由器。
- internal/handler 将请求映射到 internal/service 的领域服务，统一处理鉴权、校验、事务与事件广播；service 再调用 pkg/ 下的共享库（dbreader、storage、metrics、featureflags 等）。
- internal/daemon 在应用启动时拉起守护进程，负责 agent 任务的调度、生命周期管理与 execenv 执行环境装配，并通过 daemonws 与外部通信。
- internal/agentconfig 与各 provider 实现（agent_pkg）提供统一的 Backend 接口，由 daemon 在执行阶段按需选择具体智能体后端。
- cmd/migrate、cmd/backfill_* 等子命令复用同一套 db 连接与 service 结构，用于数据迁移与回填任务。
跨子模块的耦合点集中在：chi router 注册表、handler/service 共享结构体、daemon 的任务队列与 execenv 配置、以及 shared metrics/logger/featureflags 基础设施。
