模块按职责划分为三层：
- 入口与编排层（internal/handler + internal/service）：`handler.Handler` 通过 `New(queries, txStarter, hub, bus, ...)` 组装所有依赖（DB、realtime.Hub、events.Bus、daemonws.Hub、service.*Service、auth、analytics、llm.Client 等），以 chi 路由挂载各业务 handler；service 层封装事务边界与领域逻辑，被 handler 调用。
- 后台进程层（internal/daemon + internal/daemonws + internal/scheduler）：`daemon` 包负责 agent 进程生命周期、工作目录/技能包准备、MCP broker、GC、心跳与自动更新，并通过 `daemonws.Hub` 与 API 侧的 daemon WebSocket 通信；`scheduler` 驱动定时任务。
- 可复用能力层（server/pkg/* 与 internal/util/metrics/auth/dbreader 等）：`pkg/agent` 定义统一的 `Backend` 接口，claude/codex/copilot/cursor/openclaw/qwen 等每个 provider 实现一个文件；`pkg/db` 由 sqlc 生成 SQL 查询；`pkg/featureflag`、`pkg/llm`、`pkg/remotemcp`、`pkg/publicapi/v1` 提供跨服务复用的协议与客户端；`internal/auth`、`internal/middleware`、`internal/integrations/*` 为认证、中间件与各渠道（Slack/Lark/DingTalk/WeCom/Telegram/VCS）适配。
依赖方向严格自下而上：pkg → internal/util → internal/service → internal/handler → cmd/server；daemon 仅依赖 pkg/agent 与 internal/cli，不反向依赖 handler。
